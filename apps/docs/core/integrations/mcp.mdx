Kolab supports the Model Context Protocol (MCP) in two ways:

1. **Built-in HTTP endpoint** — every Kolab instance exposes `/api/mcp` out of the box. No extra setup, no extra process.
2. **Stdio package** (`@kolab/mcp`) — a local stdio server for clients that prefer stdio transport.

Both offer the same tools for managing workspaces, projects, tasks, comments, and labels.

## Built-in HTTP endpoint

Every Kolab API instance ships with a Streamable HTTP MCP endpoint. This is the recommended approach for self-hosted deployments.

Point your MCP client at:

```
https://your-kolab-instance.com/api/mcp
```

On first connect, you will be redirected to Kolab to sign in and explicitly approve the MCP client. After approval, all MCP tools run as your authenticated user.

The endpoint implements OAuth 2.1 with PKCE for authentication. Discovery metadata is available at:

- `/.well-known/oauth-protected-resource/api/mcp`
- `/.well-known/oauth-authorization-server/api`

## Stdio package

The `@kolab/mcp` package runs a local stdio MCP server and authenticates with Kolab using device authorization. Use this when your MCP client requires stdio transport.

### Prerequisites

- Node.js 20 or newer
- A running Kolab API
- Access to the Kolab web app to approve device login

By default, self-hosted Kolab allows both `kolab-cli` and `kolab-mcp` as device auth client IDs.

### Install and register

Use the recommended interactive installer:

```bash
npx @kolab/mcp
```

The installer lets you choose where to register the server configuration:

- Cursor (user-wide)
- Cursor (project-level)
- Claude Desktop
- Custom JSON config path

You can also run the explicit install command:

```bash
kolab-mcp install --target cursor-user -y
```

Use `--help` to see all available targets and flags:

```bash
kolab-mcp install --help
```

### Point to a self-hosted instance

When generating config, pass your Kolab base URL:

```bash
kolab-mcp install --target cursor-user -y --api-url https://kolab.example.com
```

Or set it via environment variable:

| Variable | Description |
| --- | --- |
| `KOLAB_API_URL` | Kolab API origin. Default: `http://localhost:1337`. Do not include `/api`. |
| `KOLAB_MCP_CLIENT_ID` | Device auth client ID. Default: `kolab-mcp`. |

If you override `KOLAB_MCP_CLIENT_ID`, make sure it is included in [`DEVICE_AUTH_CLIENT_IDS`](/core/installation/environment-variables).

### Authentication flow

On the first tool call that needs Kolab access, the MCP server:

1. Requests a device code from Kolab
2. Prints a verification URL and user code
3. Opens the browser when possible
4. Polls until you approve sign-in
5. Stores credentials in `~/.config/kolab-mcp/credentials.json`

## Available tools

Both the HTTP endpoint and stdio package expose the same tools:

- Session: `whoami`, `list_workspaces`
- Projects: `list_projects`, `get_project`, `create_project`, `update_project`
- Tasks: `list_tasks`, `get_task`, `create_task`, `update_task`, `move_task`, `update_task_status`
- Comments: `list_task_comments`, `create_task_comment`
- Labels: `list_workspace_labels`, `create_label`, `attach_label_to_task`, `detach_label_from_task`, `delete_label`
- Task relations: `create_task_relation`, `get_task_relations`, `delete_task_relation`

## Debugging

To run the stdio server directly:

```bash
npx @kolab/mcp serve
```

When running from source in this monorepo:

```bash
pnpm --filter @kolab/mcp run build
pnpm --filter @kolab/mcp run start
```
